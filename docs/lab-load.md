# D2: готовность данных для прогноза нагрузки лабораторий

## Итог аудита

D2 заблокирован по данным. Handoff от 19.09 содержит 767 130 направлений за
январь–март 2025 года, 20 региональных кодов и поля потока направлений. В нём
нет наблюдаемого события лабораторного исследования: отсутствуют время события,
код исследования, измерение количества и идентификатор выполняющей лаборатории.

Поэтому MAE, RMSE, peak recall и лаг между потоком направлений и лабораторной
нагрузкой не рассчитаны. Любое число сейчас было бы метрикой на придуманной
целевой переменной.

## Почему приложение 5 не заменяет фактический спрос

`data/examination_requirements.json` задаёт нормативный состав пакета перед
плановой госпитализацией. Умножение числа направлений на этот справочник может
дать сценарную верхнюю оценку требуемых исследований, но не число реально
заказанных, взятых или выполненных исследований. Оно не учитывает уже имеющиеся
результаты, назначения по показаниям, отмены, повторные заборы и место выполнения.
Этот proxy явно запрещён для отчёта D2 v1.

## Проверенное происхождение

- архив: `demeu-data-handoff-2026-09-19.zip`, SHA-256 зафиксирован в
  `scripts/lab_load/contracts.py`;
- производный parquet: `referrals_features.parquet`, SHA-256 также зафиксирован;
- использованные источники handoff: направления и список ожидающих из Ashyq Data;
- выборка ЭРСБ упомянута в инструкции скачивания, но не участвует в построении
  parquet;
- raw-хэши исходных CSV отсутствуют;
- лицензия не подтверждена, license-файла в архиве нет;
- parquet не содержит встроенных метаданных происхождения.

Агрегированные доказательства находятся в
`reports/lab-load-data-audit.json`. Исходные строки и идентификаторы в репозиторий
не копируются.

## Минимальный следующий набор

Нужен событийный ряд с полями:

1. время события;
2. регион или выполняющая организация;
3. код исследования;
4. количество единиц либо одна строка на событие;
5. стадия события: заказано, взят материал, результат готов.

Желательны privacy-preserving ключ связи с направлением и отдельные времена
заказа, забора материала и готовности результата. В методическом контракте D2
установлен непрерывный ряд минимум за 26 недель для оценки недельной сезонности;
для проверки годовой сезонности запрашиваются не менее 24 месяцев. Это проектные
пороги готовности, а не свойство текущего handoff. Вместе с выгрузкой нужны
условия использования, raw-хэши и дата снимка.

## Методика после разблокировки

- хронологические train / validation / test без перемешивания времени;
- baseline: предыдущая неделя для того же дня недели либо сезонная медиана,
  рассчитанная только по train;
- порог пика рассчитывается только по train;
- модель и лаг выбираются по validation;
- на нетронутом test публикуются MAE, RMSE, peak recall, период, размер выборки и
  baseline;
- для гипотезы потока проверяется окно 0–28 дней, а финальная корреляция или
  uplift считается только на test;
- до выполнения этих условий runtime-интеграция запрещена.

## Воспроизведение

`$HANDOFF` — каталог и архив передачи данных от 19.09; как пересобрать parquet из открытых данных, см. [referral-ml.md](referral-ml.md).

```bash
.venv/bin/python -m scripts.lab_load.audit \
  --input "$HANDOFF/referrals_features.parquet" \
  --archive "$HANDOFF.zip" \
  --output reports/lab-load-data-audit.json
.venv/bin/python -m scripts.lab_load.verify_audit reports/lab-load-data-audit.json
.venv/bin/python -m scripts.lab_load.build_blocker_report \
  --audit reports/lab-load-data-audit.json \
  --output reports/lab-load-v1.json
.venv/bin/python -m scripts.lab_load.verify_report reports/lab-load-v1.json
.venv/bin/python -m unittest discover -s tests/lab_load -p 'test_*.py'
.venv/bin/ruff check scripts/lab_load tests/lab_load
```
