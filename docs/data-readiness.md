# Аудит данных организаторов

`scripts/audit-referral-data.ts` проверяет локальные CSV перед разработкой D1, D2, B3 и D4. Он не обучает модели и не подтверждает готовность к обучению. Без входа все источники имеют `missing_data`, задачи — `blocked`.

```bash
npx tsx scripts/audit-referral-data.ts
npx tsx scripts/audit-referral-data.ts --config data/processed/organizer-audit-config.json
```

Код выхода: `2` — есть блокеры данных, `0` — для всех задач требуется семантическая проверка, `1` — ошибка конфигурации/запуска. Код `0` не означает готовность моделей. Отчёт JSON выводится в stdout; ошибки содержат только фиксированные коды. Запуск не требует ключей и не обращается в сеть.

Конфигурация перечисляет только явно разрешённые локальные файлы. Относительные пути считаются от каталога конфигурации. Скрипт не сканирует каталоги. Пример ниже иллюстрирует форму, а не фактические поля ЕИП:

```json
{
  "sources": [{
    "source": "eip",
    "file": "../raw/organizers/lab.csv",
    "columns": {
      "period": "Период",
      "region": "Регион",
      "test_type": "Тип исследования",
      "test_count": "Количество"
    }
  }]
}
```

Источники: `is_bg`, `ersb`, `eip`. Смысл столбцов задаёт человек, сопоставление точное; по похожему названию поле не угадывается. Повторное использование одного столбца для разных смыслов запрещено. ЕРСБ учитывается в инвентаризации, но наличие его колонок не подменяет метки ИС БГ или ряд ЕИП.

Поддерживается только UTF-8 CSV с запятой, LF/CRLF, кавычками и удвоенными кавычками. Размер одного файла ограничен 10 MiB, конфигурации — 64 KiB. Неверный quoting, повторные/пустые заголовки, строки разной ширины, пустой набор, неизвестный формат блокируют проверку. XLSX, Parquet, иной разделитель и кодировка требуют отдельной поддержки либо явной локальной конвертации; скрипт не пропускает их молча. На крупных реальных выгрузках потребуется следующий срез потоковой обработки: текущий лимит не является требованием к размеру данных проекта.

Отчёт содержит SHA256, размер, число строк, сопоставленные семантические ключи, отсутствующие столбцы и число пустых ячеек. Ноль не считается пропуском; условные значения вроде `NULL` пока не интерпретируются. Пути, исходные заголовки, значения идентификаторов, даты пациентов и свободный текст в отчёт не попадают. Сырые данные хранить в игнорируемом `data/raw/`, конфигурацию и локальные результаты — в `data/processed/`.

Статусы `blocked` и `needs_semantic_review` намеренно не содержат варианта `ready`. Наличие заголовков и непустых ячеек не подтверждает типы, даты, смысл статусов, зрелость исходов или отсутствие утечки. Эти проверки перечислены в `pending_reviews`; их нужно выполнить после получения словаря данных. Текущий инструмент не проверяет связки между источниками, качество моделей, юридическую применимость или достаточность выборки.

| Задача | Технические предпосылки текущего варианта | Что обязательно проверить после сопоставления |
|---|---|---|
| D1 | Регистрация, госпитализация, статус/дата, организация/уровень, профиль, условия помощи | Точка и горизонт прогноза, незавершённое ожидание и отмены, временной holdout, покрытие организаций, определение перегруженности |
| D2 | Период, регион, тип исследования, количество | Единицы и гранулярность, пропущенные периоды отдельно от нулей, горизонт/backtest; мощности и нормы для смен/реагентов |
| B3 | Направление, регистрация, дата исхода, причина отказа, пакет/дата снимка, дата признаков, профиль/уровень | Словарь причин, зрелые исходы, справочник требований к пакету, признаки до решения, временной holdout, баланс классов |
| D4 | Направление, плановая дата, явка/дата исхода, дата признаков | Значение явки, зрелые исходы, отмены/переносы, признаки до события, временной holdout, баланс классов |

Это предварительные требования к варианту с отдельными направлениями. Они не объявляются контрактом фактических выгрузок: если источник содержит только агрегаты или готовую длительность, постановку и конфигурацию аудита нужно пересмотреть явно. Статус отсутствующего поля означает отсутствие предпосылки этого варианта, а не доказанную невозможность любого прогноза.

Внешние блокеры: сами файлы ИС БГ/ЭРСБ/ЕИП и доступ к ним, словарь полей/статусов, период и дата выгрузки, правила использования/публикации, первоисточник нового ТЗ/PRD. Для B3 отдельно нужен проверенный справочник комплектности. Для D4 отсутствие целевой метки явки означает отмену условной задачи, как указано Арданом. DDXPlus и июльские метрики этих пробелов не закрывают.
