# Восстановление опроса в workspace режиме

При настроенном workspace успешный `/api/chat/start` выдаёт HttpOnly SameSite=Strict cookie с подписанным правом на конкретную сессию. В production cookie Secure, область пути `/api/chat`. Подпись использует `DEMEU_AUTH_SECRET` с отдельным назначением HMAC; роль врача или знание чужого sessionId это право не заменяют. Частичная настройка workspace не включает старый открытый режим. Все POST этого потока требуют same-origin.

`/api/chat`, `/api/chat/finalize` и новый `POST /api/chat/resume` проверяют cookie, sessionId, срок подписи и TTL записи. Resume принимает `{ sessionId, token }`, дополнительно проверяет исходную ссылку и отдаёт `{ sessionId, language, messages, turnsLeft, status, result? }`. Создания новой сессии, LLM и повторной доставки на этом пути нет. Completed восстанавливает итог, aborted отображается как завершившийся срок опроса. Смена серверного секрета отзывает ранее выданные права.

Браузер хранит только sessionId в sessionStorage текущей вкладки, с ключом исходной ссылки. При перезагрузке пытается восстановить уже начатый после согласия опрос. Отсутствующее/истёкшее право или отсутствующая запись возвращают к экрану согласия, без автоматического старта. Ошибка сети оставляет возможность повторить восстановление. Сообщения и результат не сохраняются в sessionStorage. При запрете browser storage восстановление недоступно.

Без настройки workspace старые маршруты продолжают прежнее поведение, resume недоступен. Полный `TriageResult` по-прежнему доступен авторизованному пациентскому браузеру после завершения, как в старом API; новый безопасный DTO результата не вводится молча.

Cookie допускает несколько независимых сессий в браузере, срок ограничен суммой TTL опроса и retention результата. Публичные chat/finalize/resume выполняются последовательно для одного sessionId, включая чтение истории и LLM. Разные сессии работают параллельно. Периодический sweep ждёт уже зарегистрированные операции и временно удерживает новые до окончания очистки. Внутренняя финализация из chat не входит в ту же очередь повторно.

Статический start использует тот же барьер: проверка истёкшего токена может каскадно удалить его сессии и потому ждёт уже начатые операции. Вызова LLM внутри start нет. Новая защита читает не более 16 KiB тела запроса; превышение возвращает 413, включая chunked запрос без Content-Length.
