# Demeu — техническое описание

Перенесено из корневого README 28.09.2026. Актуализировано по финализации 04.10.2026; исторические измерения сохранены. Продуктовое описание, кастдев, хроника по неделям и статус — в корневом [README](../README.md).

## AI-триаж и первичный сбор анамнеза

Demeu — MVP для госполиклиник: врач создаёт персональную ссылку, пациент
проходит короткий диалог, а аналитический слой формирует предварительную
гипотезу, приоритет срочности, маршрут к специальности и объяснение. При
настроенном Telegram-боте врачу отправляются структурированный текст и PDF.

Продукт **не ставит диагноз**. Красные флаги и правила безопасности имеют
приоритет над моделью, а финальное решение принимает врач.

## Что работает в MVP

1. Врач создаёт персональную ссылку на главной странице.
2. Пациент подтверждает начало опроса и отвечает в веб-чате по ссылке
   `/c/<token>`.
3. LLM-адаптер извлекает анамнез и структурированный вектор признаков.
4. Правила проверяют красные флаги только в репликах пациента. LR-модель
   ранжирует патологии, а таблица маршрутизации агрегирует вероятности по
   специальностям и задаёт базовую срочность.
5. При низкой уверенности модель воздерживается, и работает LLM-fallback; при
   отказе адаптера остаётся rules-only путь. Emergency-правила доминируют в
   любом режиме.
6. После завершения сводка сохраняется в сессии и отправляется врачу через
   собственного Telegram-бота. Повторная финализация идемпотентна.

Explainability строится из цитат пациента, причин срочности, top-вкладов
признаков и уверенности. Веб-интерфейс врача и пациента — принятый продуктовый
дизайн. Июльский MVP дополняется опциональным рабочим кабинетом ниже.

## Production и рабочий кабинет

Канонический адрес: [кабинет](https://specimen-ai.govtech-kz.com/workspace),
[API-портал](https://specimen-ai.govtech-kz.com/api-docs). Актуальная
конфигурация общего VPS, безопасный выпуск и откат описаны в
[инструкции Astana Hub](production-astana-hub.md). Прежний сервис на
`84.247.161.211` — исторический стенд; его актуальное состояние не проверено.

В приложении реализован `/workspace`: отдельные учётные записи врача,
владельца организации и аналитика; направления, подтверждения внешних фактов
врачом, история исправлений и описательные сводки. Неизвестные очередь, дата
госпитализации и явка остаются пустыми. Срок годности и наличие результата
обследования проверяются раздельно; отправка не выводится из комплектности.

Кабинет переработан: общая боковая навигация, рабочий обзор, реестр направлений,
опросы, календарь подтверждённых дат, история подтверждений, аналитика,
качество данных и настройки. Карточка направления разделена на пять вкладок.
Врач видит свою область, владелец — организацию, аналитик — только допустимые
агрегаты без персональных карточек. Интерфейс адаптирован для узких экранов.
Состав страниц и границы проверки: [отчёт о переработке](workspace-redesign.md).

Файловый adapter сохраняет данные на локальном volume одного Node-процесса.
В режиме кабинета опрос восстанавливается после перезагрузки вкладки по
отдельному пациентскому праву доступа. История направления отделена от TTL
опроса; полный транскрипт в неё не переносится. Врач получает отдельную
пациентскую памятку, которую можно передать пациенту, вместо полного
врачебного PDF. При неопределённой внешней доставке автоматического повтора нет.

## Быстрый локальный запуск

Для демонстрации без ключей и внешних сервисов:

```bash
npm ci
npm run demo:mock
```

Команда открывает кабинет на <http://127.0.0.1:3240/workspace>. Учебные
учётные записи: `doctor-a`, `doctor-b`, `analyst`, `owner`; общий пароль
`DemeuDemo2026!`. Адрес ссылки пациента и локального ящика уведомлений
печатаются в терминале. В ящике можно скачать сформированный PDF.
Диалог и отправка уведомлений имитируются локально; правила, модель,
кабинет и PDF работают через обычные маршруты приложения. Все записи
вымышлены и хранятся во временном каталоге до остановки `Ctrl+C`.
Однократная проверка с автоматической остановкой: `npm run demo:mock -- --check`.

Для запуска с настоящими внешними сервисами нужны Node.js 24 и npm.
Реальные ключи не должны попадать в git.

```bash
npm ci
cp .env.example .env
npm run dev
```

Откройте <http://localhost:3000>, создайте ссылку и пройдите путь пациента в
новой вкладке. Для живого диалога нужен `ANTHROPIC_API_KEY`; без Telegram-
реквизитов сводка формируется, но внешняя доставка недоступна.

Проверки без внешней сети:

```bash
npm run lint
npx tsc --noEmit
npm test
npm run build
npm run eval -- --allow-unvalidated --check
```

### Переменные окружения

| Переменная | Назначение |
|---|---|
| `ANTHROPIC_API_KEY` | Живой LLM-адаптер диалога и анализа |
| `TELEGRAM_BOT_TOKEN` | Токен собственного Telegram-бота |
| `TELEGRAM_DOCTOR_CHAT_IDS` | Получатели врачебной сводки: числовые `chat_id` через запятую; порядок сохраняется, повторы удаляются |
| `TELEGRAM_DOCTOR_CHAT_ID` | Legacy-настройка одного получателя; используется только если plural-настройка не задана или пуста |
| `DOCTOR_ACCESS_CODE` | Опциональная защита создания ссылок |
| `APP_BASE_URL` | База персональной ссылки; локально `http://localhost:3000` |
| `APP_PORT` | Loopback-порт приложения за host proxy; на общем VPS организаторов `8019` |
| `DEMEU_PROCESSING_MODE` | `external_llm` (по умолчанию) или `deterministic`; второй режим использует фиксированный RU/KK опросник и не требует `ANTHROPIC_API_KEY` |
| `DEMEU_DOMAIN` | Production `specimen-ai.govtech-kz.com` либо безопасный lowercase ASCII FQDN; `APP_BASE_URL` обязан быть точным `https://<DEMEU_DOMAIN>` |
| `NODE_ENV` | Режим Next.js |
| `TLS_BRANCH` | На общем VPS организаторов — `branch-a-caddy`: TLS завершает host Caddy; локальный runtime её не использует |
| `DEMEU_DATA_DIR` | Опциональный приватный каталог файлового хранилища; без него остаётся память |
| `DEMEU_ACCOUNTS_FILE` | Явный путь к приватному файлу учётных записей вне репозитория |
| `DEMEU_AUTH_SECRET` | Отдельный секрет подписи прав доступа, минимум 32 байта; без дефолтного значения |
| `DEMEU_HOST_MIS_CREDENTIALS_FILE` | Опциональный приватный абсолютный host-путь; stock deploy добавляет проверенный read-only mount |
| `DEMEU_MIS_CREDENTIALS_FILE` | Внутри контейнера `/run/secrets/demeu-mis-credentials.json`; отдельные сервисные credentials, ротация проверяется на каждом запросе |
| `DEMEU_MIS_RESEARCH_EVENTS` | Только точное `I_ACKNOWLEDGE_RESEARCH_ONLY` включает экспорт исследовательских событий B3; по умолчанию выключен |


Три настройки кабинета в `.env.example` закомментированы: включайте их
согласованно по [инструкции](workspace-accounts.md). Частичная настройка
закрывает доступ с ошибкой, а не включает обход через общий код врача.
В режиме кабинета сводки адресуются только текущему владельцу записи;
отсутствие личного получателя не включает общую рассылку.

В режиме `deterministic` ответы пациента не передаются внешней языковой модели:
вопросы и сводка формируются детерминированными правилами. Telegram остаётся
отдельным каналом доставки врачу, поэтому этот режим не означает, что все
данные хранятся или передаются только локально.

В legacy-режиме без кабинета Telegram остаётся односторонним каналом. Сводка и PDF либо короткое
уведомление о прерванном опросе рассылаются всем настроенным получателям.
Сбой одного получателя не блокирует остальных; `deliveryStatus` отражает
агрегат по сессии и становится `failed`, если обязательный текст не дошёл
хотя бы одному адресату. Каждый отдельно доставляемый текстовый chunk содержит
обязательную оговорку и укладывается в лимит 4096 символов. Ошибка PDF не
меняет успешную доставку текста.

### Docker

```bash
cp .env.example .env
docker compose up --build -d
curl --fail http://localhost:3100/api/healthz
```

Compose по умолчанию публикует приложение только на loopback. В текущем
production-профиле приложение слушает `127.0.0.1:8019`, а общий host Caddy
организаторов обслуживает 80/443 и сертификат для
`specimen-ai.govtech-kz.com`. Bundled Caddy на общем VPS не запускается.
История прежних bare-IP и magic-DNS конфигураций сохранена в документации как
датированное evidence, но не является актуальной инструкцией запуска.

## Что подтверждено живыми проверками (исторические evidence)

- Один локальный end-to-end прогон срочного сценария прошёл через API, два
  запроса Anthropic, анализ, PDF и доставку. Итог сохранил `emergency` и
  `chest_pain`; LR-модель безопасно воздержалась с `low_confidence`, поэтому
  результат пришёл из `llm_fallback` без неподтверждённых патологий и вкладов.
- Telegram Bot API принял `sendMessage` и `sendDocument` с HTTP 200. Это
  подтверждает принятие запросов API, но не прочтение сводки человеком.
- LR-модель подключена в production runtime; Python↔TypeScript parity зелёный
  на 150/150 примерах, а `/api/healthz` берёт `model_version` из загруженного
  артефакта.
- Для VPS организаторов подтверждены rootless Docker/Compose, общий host Caddy,
  свободный loopback-порт 8019, DNS и доверенный TLS нового домена. Старый
  production описан историческими evidence; новая версия требует exact-SHA
  deploy, L1 и сверки восстановленных данных. Платные сценарии 2–3 не запускались без отдельного
  разрешения стоимости.

## Данные и методология

Ниже восемь явных пунктов data-критерия. Проверенные факты воспроизводятся
офлайн-скриптами; публичные показатели качества берутся только из
[`eval/report.json`](../eval/report.json), рассчитанного TypeScript-путём.

### 1. Источник и происхождение

Используется синтетический медицинский датасет **DDXPlus v15**: официальный
[Figshare article 20043374](https://figshare.com/articles/dataset/DDXPlus_Dataset/20043374),
DOI `10.6084/m9.figshare.20043374.v15`. Локальный provenance фиксирует URL,
версию, дату получения, идентификаторы файлов и контрольные суммы в
`data/raw/PROVENANCE.json`; сырые файлы в git не входят.

### 2. Лицензия и атрибуция

Лицензия — [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) по
metadata официальной страницы Figshare. В опубликованном file list отдельного
LICENSE не было; локальный `data/raw/LICENSE` — запись provenance на основе
metadata, а не самостоятельный файл лицензии издателя.

### 3. Структура и объём

Релиз содержит словарь evidences, словарь патологий и CSV split-файлы с
`AGE`, `SEX`, `PATHOLOGY`, `EVIDENCES`, `INITIAL_EVIDENCE` и
`DIFFERENTIAL_DIAGNOSIS`. Фактические raw-размеры train/validate/test:
**1 025 602 / 132 448 / 134 529** строк. Найдено **223 evidences**
(208 binary, 10 categorical, 5 multi-choice), **49 raw-патологий** и непустой
`icd10-id` у **49/49**. Шкала severity: 1–5, меньшее значение означает более
тяжёлое состояние.

### 4. Очистка и разделение выборок

Проект работает только со взрослыми (`AGE >= 18`) и удаляет полные дубли по
ключу `(AGE, SEX, PATHOLOGY, EVIDENCES)`. После adult-only фильтра и
внутрисплитовой дедупликации осталось **814 240 / 108 199 / 109 732** строк.
Затем decontamination с приоритетом train → validate → test удалила пересечения
между split: финальные размеры — **814 240 / 104 770 / 105 723**, а все три
попарных overlap равны **0**. Из adult-only label space исчезли исключительно
детские классы Bronchiolitis и Croup; runtime `class_order` содержит
**47** классов.

### 5. Признаки и целевая переменная

Цель LR — родная метка `PATHOLOGY`, а не срочность и не специальность:
таких целевых меток в DDXPlus нет. Вектор содержит **975 признаков**:
972 one-hot evidence-колонки и `age_norm`, `sex_m`, `sex_f`. Порядок и
препроцессинг читаются из `models/triage-lr-v1.json`, поэтому Python-обучение и
TypeScript-инференс используют один контракт. C/M значения кодируются как
`E_x@V_y`; неизвестные признаки не превращаются в выдуманные колонки.

### 6. Почему multinomial logistic regression

LR соответствует закрытому многоклассовому label space, выдаёт вероятности,
работает на разреженном one-hot векторе, быстро и детерминированно исполняется
в TypeScript и позволяет показать вклад каждого признака. Артефакт — один JSON,
Python в production-образ не входит. Порог воздержания финальной модели —
`0.5036984086036682`; model fallback остаётся частью рабочего пути. Срочность и
маршрутизация выводятся отдельной прозрачной таблицей, а safety-правила всегда
побеждают вероятностный результат.

### 7. Методика оценки

Eval содержит **48 карточек**: 28 `flat`, 12 `dialog` и 8 ручных red-flag
сценариев (5 позитивных и 3 негативных). DDX-карточки детерминированно
отрендерены из decontaminated held-out строк; родная `PATHOLOGY` остаётся gold.
Прогон выполняет `scripts/eval.ts` через production `lib/model.ts` и
`lib/triage.ts`. Publication guard пересчитывает агрегаты из `per_case`,
проверяет SHA входов и блокирует подменённые показатели.

### 8. Ограничения данных и оценки

- DDXPlus — синтетика и не доказывает качество на пациентах Казахстана.
- Демо №2 с болью в пояснице находится вне label space. Для демо №3 есть
  классы-кандидаты, но покрытие конкретного сценария не доказано.
- Таблица `data/pathology_map.json` имеет `validated:false`; результаты
  routing/urgency нельзя трактовать как врачебную или клиническую валидацию.
- Текущий eval работает в режиме `no-LLM` с идеализированным структурированным
  extraction input. Он измеряет верхнюю границу модели и не доказывает качество
  извлечения из живого чата end-to-end.
- M9/M10 extraction F1 в этом режиме не запускались и остаются `null/not_run`.

## Качество: только production TypeScript eval

Источник таблицы — текущий `eval/report.json`; показатели Python-обучения здесь
не публикуются. Режим — **`no-LLM`**: модель получила идеализированный
структурированный extraction input. Поэтому Top-1/Top-3 не являются метрикой
извлечения или полного chat end-to-end пути.

## Ограничения MVP

- Без `DEMEU_DATA_DIR` сессии хранятся in-memory и очищаются при перезапуске. Опциональное файловое хранилище сохраняет состояние, но требует одного процесса и локального приватного каталога; сроки жизни сессий продолжают действовать.
- Пациентский доступ к подготовке отделён от TTL опроса: уникальная ссылка
  действует 30 дней, поддерживает отзыв и перевыпуск. Сохранённые отметки
  пациента требуют явного подтверждения назначенным врачом.
- Врачебная валидация таблицы маршрутизации ещё не проведена.
- Один production-прогон подтверждает срочный сценарий, но не заменяет
  сценарии 2–3 и не подтверждает прочтение Telegram-сводки человеком.
- MVP не выполняет запись пациента, напоминания и последующее сопровождение.

## Стек

Next.js 15.5 (App Router), React 19, TypeScript, Anthropic SDK, Docker,
собственный Telegram Bot API adapter. Python используется только офлайн в
`scripts/`; production runtime загружает JSON-артефакт модели.

## Контракты финализации

Уникальный пациентский доступ, отдельные отметки пациента, аудируемые правки
врача и контекст оперативного/консервативного лечения описаны в
[контрактах финализации](finalization-contracts.md). Оба нормативных каталога
остаются `validated:false`; их наличие не подтверждает готовность к приёму.
API MIS — отдельные сервисные credentials по организации, durable outbox,
lease/ACK, монотонная последовательность и идемпотентные повторы. Доступ по
cookie кабинета не заменяет MIS-аутентификацию. Реальные реквизиты МИС отсутствуют.

Правила безопасности остаются единственным runtime-детектором красных флагов.
Текущий offline refresh связывает source/runner/corpus/predictions SHA; история
Qwen/Jev и исходных правил сохранена побайтно. Это регрессия на том же
синтетическом корпусе, не доказательство клинического качества.

Schema6 и первый переход от markerless образа требуют поддержанного плана
восстановления; см. [stock deployment](../deploy/DEPLOY.md). Автоматический
fallback никогда не запускает старый reader поверх несовместимого snapshot.

## Интеграционный finalization smoke

[`scripts/finalization-smoke.mjs`](../scripts/finalization-smoke.mjs) проверяет
единый локальный путь RU/KK chat → кабинет врача → заключение → patient package
и PDF → B3 registration snapshot → MIS pull/ACK → aggregates/OpenAPI. Он
запускает приложение в отдельной копии без общего `.next`, с приватными
accounts/storage/MIS credentials и loopback Telegram mock.

Child environment задаётся allowlist. `DEMEU_PROCESSING_MODE=deterministic`,
Anthropic credentials и endpoint отсутствуют, поэтому верхняя граница запросов
к Anthropic равна нулю. Fetch guard блокирует остальные внешние адреса. Smoke
перезапускает приложение на том же безопасном хранилище и проверяет отсутствие
повторной MIS/Telegram доставки, затем искусственно старит только completed
source session и доказывает сохранение исходного patient URL и referral после
24-часового retention.

Результат содержит только агрегированные флаги доказательств. Process groups
завершаются с bounded timeout, временные каталоги удаляются, а порты должны
успешно bind повторно до зелёного результата. Полный контракт и внешние handoff
gates описаны в [finalization acceptance](finalization-acceptance.md).
