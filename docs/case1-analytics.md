# Аналитика кейса 1: нагрузка стационаров по открытым данным ИС БГ

Ожидаемый результат ТЗ кейса 1: данные → аналитика по медицинским организациям и регионам → прогноз нагрузки → объяснение факторов. Этот документ описывает, как это собрано и в каком формате отдаётся экрану.

## Данные

Источник — открытый набор ИС «Бюро госпитализации» на Ashyq Data (data.gov.kz, `mz_bg_planned_hospitalization_referrals`): 767 130 направлений на плановую госпитализацию, зарегистрированных с 01.01 по 31.03.2025, исходы (госпитализация или отказ) наблюдаются до 13.05.2026. Это данные, которые NITEC назвал данными кейса на консультации 18.09. Расширенную выгрузку (два года, регистры) команда запросила, ответа пока нет.

В части строк дата госпитализации в источнике предшествует дате регистрации направления: у отдельных организаций это даёт отрицательные агрегаты ожидания. Срез сохраняет такие значения для аудита источника, а интерфейс показывает их как «Не рассчитано», не как отрицательное число дней. Если по внешним направлениям нет госпитализаций, показатели ожидания могут быть `null`; отсутствие `long_wait_vs_expected` означает, что сравнение не рассчитано, а не нулевой результат.

Регион берётся из первого блока `hospitalization_code`: это код КАТО направившей организации, он заполнен у всех строк (у 1132 из 1140 направляющих организаций ровно один код). Склейка с набором «Ожидающие» по времени регистрации не используется: она неоднозначна.

## Воспроизведение

```bash
bash scripts/case1_analytics/download.sh data/raw/case1        # ~660 МБ, git-ignored
python -m scripts.case1_analytics.build_aggregates --raw data/raw/case1
# -> data/case1/aggregates.json, ~15 секунд
```

Зависимости — `scripts/case1_analytics/requirements.txt`; проверено на pandas 2.2.2 и 3.0.6, результат одинаковый. Повторный запуск даёт тот же JSON, кроме `generated_at`. Хэши входных файлов пишутся в `source.inputs`: при другой выгрузке портала результат будет отличаться, и это видно.

Таблица признаков для моделей B3 и D1 (`scripts/referral_ml`) собирается из тех же открытых данных плюс набора «Ожидающие»: `python -m scripts.case1_analytics.build_features`. Что совпадает с зафиксированной передачей от 19.09, а что нет — в docstring скрипта и в [referral-ml.md](referral-ml.md).

## Что считается

| Блок JSON | Содержание |
|---|---|
| `national` | итоги по стране; `external_24h` — очередь в собственном смысле: направление из другой организации на круглосуточную койку |
| `regions[]` | 20 регионов КАТО: направления, отказы, ожидание (медиана, p90, доля > 30 дней), доля лечащихся в другом регионе, помесячно |
| `hospitals[]` | 642 организации с ≥ 300 направлениями за квартал: те же показатели, регион, топ профилей, отказы и длинные ожидания против ожидаемых, прогноз на март, `signals` |
| `profiles[]` | профили коек с ≥ 1000 направлений |
| `factors[]` | доля отказов по факторам и отношение к средней по стране (`lift`) |
| `forecast` | прогноз поступлений на месяц вперёд с метриками против базовых прогнозов |
| `signals_summary` | сколько организаций с сигналами, топ-15 по лишним отказам |
| `definitions`, `limitations` | определения и ограничения — показывать на экране рядом с цифрами |

**Сигнал перегрузки.** Коечного фонда в открытых данных нет, поэтому перегрузка — косвенный сигнал. Для каждой организации ожидаемое число отказов (и ожиданий > 30 дней) считается по средним по стране долям в той же группе «профиль × цель × самонаправление». Сигнал ставится, если 95 % интервал отношения «факт / ожидание» целиком выше 1,5. Так организация не попадает в список только потому, что у неё тяжёлый профиль.

**Прогноз.** Цель — поступления в каждую организацию за март 2025, прогноз сделан на данных, известных на 01.03. Среднее двух оценок: (1) поток: направления, ожидающие на 01.03, × доля поступивших за месяц плюс новые направления (темп февраля на рабочий день × 17 рабочих дней марта) × доля поступивших в месяц регистрации; доли выучены на феврале; (2) февраль, пересчитанный по рабочим дням.

| Вариант | WAPE по 642 организациям |
|---|---|
| Февраль на 31 календарный день | 27,8 % |
| Февраль по рабочим дням | 12,8 % |
| Модель потока | 13,2 % |
| Среднее (итог) | 12,1 % |

Главный вклад — производственный календарь: в марте 2025 было 17 рабочих дней против 20 в феврале (перенос 8 Марта, Наурыз). Итоговый вариант выбран из трёх после сравнения на марте, поэтому март для этого выбора не полностью отложенный; все варианты лежат в JSON. По стране: прогноз 175 865, факт 176 416.

## Ограничения

Один квартал: сезонности и тренда не видно. Причина отказа не публикуется. Строки — направления, не пациенты. ЭРСБ (пролеченные случаи) и ЕИП (лаборатории) в срез не входят. Полный список — `limitations` в JSON.

## Для экрана (Алмаз)

Экран «Аналитика ведомства» для ролей руководитель и аналитик, читает `data/case1/aggregates.json` на сервере; тот же JSON отдаётся `GET /api/analytics/case1` под текущей авторизацией API.

1. Шапка: источник, период, дата выгрузки, «офлайн-срез, пересчитывается скриптом».
2. Страна: четыре числа из `national.external_24h` — направления, отказы %, медиана и p90 ожидания.
3. Регионы: таблица из `regions[]` с сортировкой по отказам и доле > 30 дней, значения `external_24h`.
4. Организации: таблица из `hospitals[]` с фильтром по региону и флажками `signals`; в карточке — факт против ожидаемого с интервалом, топ профилей, прогноз на март (прогноз / факт / из очереди / новые).
5. Прогноз: таблица метрик из `forecast` (итог, модель потока, два базовых) и итог по стране.
6. Факторы: `factors[]` полосками `lift`.
7. Внизу — `limitations` целиком.

Синтетическое сравнение организаций в `app/workspace/insights.ts` на этом экране не использовать.

## Runtime-контракт

`GET /api/analytics/case1` доступен только авторизованным ролям `owner` и `analyst`. Роль `doctor` получает `403 FORBIDDEN` и продолжает видеть собственную локальную сводку из `/api/workspace/aggregates`; ведомственный файл при таком запросе не читается. Query-параметры отклоняются с `400 BAD_REQUEST`, остальные методы — с `405 METHOD_NOT_ALLOWED`. Ответы имеют `Cache-Control: no-store` и `X-Content-Type-Options: nosniff`.

Сервер читает `data/case1/aggregates.json` лениво, проверяет размер, отсутствие symlink, точную схему v1 и согласованность итогов. Отсутствующий или повреждённый файл даёт fail-closed `503 CASE1_ANALYTICS_UNAVAILABLE`. Валидатор не фиксирует текущие количества регионов и организаций как вечные константы: новый воспроизводимый срез той же схемы разрешён, если внутренние итоги и ссылки согласованы. Docker runner явно включает JSON в `/app/data/case1/aggregates.json`.

Экран руководителя и аналитика показывает семь блоков из артефакта: происхождение, четыре национальных показателя, регионы, организации с фильтрами и косвенными сигналами, ретроспективный прогноз, факторы и полный список ограничений. Для прогноза рядом с метриками указано, что итоговый вариант выбран после сравнения на марте и март не является независимым отложенным периодом. Компоненты `from_pending` и `from_new` подписаны как оценки модели потока; их сумма не представляется разложением итогового усреднённого `forecast`.
