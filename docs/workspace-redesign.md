# Кабинет: итог локальной переработки

Дата: 13.09.2026. Worktree `september-foundation`, база `7076e8a`, изменения не закоммичены и не развёрнуты на VPS. Задачи ClickUp являются PRD. План, референсы и принятые ограничения: [workspace-redesign-plan.md](workspace-redesign-plan.md).

## Реализовано

Общая оболочка с боковой навигацией, контекстом текущей роли, новым входом, обработкой потери доступа, мобильным меню и клавиатурным фокусом. Локальный IBM Plex Sans, компактные карточки и таблицы; пациентская визуальная тема не изменена. Новых зависимостей нет.

| Раздел | Содержание |
|---|---|
| Обзор | Показатели разрешённых записей, текущие этапы, ближайшие даты, сведения для проверки, последние подтверждения |
| Направления | Поиск, фильтры, отдельная форма создания вручную или из завершённого опроса |
| Карточка | Обзор, факты, обследования, история, пациентская памятка; конфликт версии требует обновления, а не автоматического повтора |
| Опросы | Разрешённые опросы, сводка, доставка, создание ссылки пациенту |
| Календарь | Месячная сетка и список подтверждённых дат; дата не превращается в явку |
| История подтверждений | События направлений с автором и временем; не общий аудит системы |
| Аналитика | Описательные агрегаты; дополнительные профили и локальная история только для врача/владельца |
| Качество данных | Известные и неизвестные сведения, знаменатели и ограничения источников |
| Настройки | Текущая учётная запись, организация, роль и реальные границы доступа; изменение конфигурации оператором |

Врач видит свои записи, владелец — организацию. Аналитик не запрашивает персональные направления/опросы и не получает их через прямой URL. Малые группы и неизвестные агрегаты не превращаются в нули. Карточка привязана к загруженному идентификатору; запоздалые ошибки прежнего сеанса не сбрасывают новый вход.

## Проверка

- Финальный Vitest: 1101 passed, 4 skipped; 73 файла passed, 1 skipped. `npm run lint`, `npx tsc --noEmit`, `npm run build`, `npm run eval -- --mode no-llm --allow-unvalidated --check` и `git diff --check` завершились успешно. Build предупреждает о двух lockfile в основном checkout/worktree; сборке это не помешало.
- Playwright/Chrome: 29 посещений страниц для двух врачей, владельца и аналитика; проверены разделение областей и запрет прямого доступа аналитика к карточкам.
- Создание направления, независимые подтверждения с неизвестной явкой, исправление, конфликт revision 409 с сохранением намерения и без автоматического повторения, обследование, история, получение PDF.
- Отсутствующий получатель Telegram: явный 503 и понятное сообщение; внешняя отправка не выполнялась.
- Мобильные страницы на ширине 390 px и дополнительные проверки на 320 px: без горизонтального переполнения. Меню: начальный фокус, 13 последовательных Tab внутри навигации и возврат по Escape.
- Текущий 403 скрывает записи и не вызывает цикл повторной загрузки. Запоздалый 401 прежнего входа не сбрасывает нового пользователя; текущий 401 удаляет персональные строки и возвращает форму входа.
- После перезапуска локального сервера все 17 синтетических направлений сохранились; повторный вход через UI успешен.

Проверки используют отдельный временный каталог и вымышленные данные. Mock E2E очищает унаследованную конфигурацию кабинета и исключает runtime snapshots из копии проекта. Четыре теста локального живого отчёта пропущены при отсутствии артефакта; это не подтверждение живого API или доставки.

## Что остаётся внешним

- Проверенный нормативный справочник: без него нормативная комплектность неизвестна.
- Фактические выгрузки и определение целевых показателей для D1/D2/B3/D4: прогнозы не подменены случайными числами.
- Ответы Ардана о процессе, ролях, источниках и правилах пилота: [20 вопросов](ardan-questions.md). Создание задачи и комментария отклонено лимитом ClickUp; ничего не опубликовано.
- Реальные реквизиты интеграций и отдельная проверка доставки; разрешение и условия работы с персональными данными; операторский деплой.

Файловое хранилище рассчитано на один процесс, не на несколько реплик. Страницы настроек не имитируют управление сотрудниками. Локальный UI и mock E2E не означают клиническую валидацию или готовый production rollout.
