# Подготовка workspace к эксплуатации

Это инструкция оператору; запуск на VPS в этой итерации не выполнялся. Перед включением персонального потока требуется утвердить условия хранения и доступа. Используется один Node-процесс на локальном диске, без NFS, cluster и параллельных writers.

Для назначенного пользователем 14.09.2026 нового VPS см. [отдельную конфигурацию и команды](new-server-2026-09.md). Актуальные `deploy/deploy.sh` и `deploy/rollback.sh` всегда подключают workspace overlay; для текущего origin `84.247.161.211` они также подключают `compose.new-server-ip.yml` после него.

## Приватные файлы

Оператор заранее создаёт абсолютный каталог данных с владельцем UID/GID 1001:1001 и правами 0700. Отдельный JSON учетных записей, описанный в `workspace-accounts.md`, должен быть обычным файлом с правами 0600 и владельцем 1001:1001; каталог размещения также должен быть приватным. Хеши паролей не заменять открытыми паролями. Приложение в Docker работает как UID 1001.

Для Compose задать `DEMEU_HOST_DATA_DIR` и `DEMEU_HOST_ACCOUNTS_FILE` абсолютными host-путями. Overlay `deploy/compose.workspace.yml` самодостаточен: монтирует каталог в `/var/lib/demeu`, accounts JSON read-only в `/run/secrets/demeu-accounts.json`, устанавливает контейнерные `DEMEU_DATA_DIR` и `DEMEU_ACCOUNTS_FILE`. `create_host_path: false` не позволяет молча создать каталог вместо отсутствующего файла. Дополнительно подключать `compose.storage.yml` не нужно.

`DEMEU_AUTH_SECRET` длиной не менее 32 байт оператор задаёт в существующем приватном `.env` приложения; он попадает в контейнер через базовый `env_file`, не через Docker build или текст overlay. `APP_BASE_URL` должен совпадать с внешним HTTPS origin. Файлы учетных записей и runtime-состояния не класть в build context; `data/runtime/` специально исключён из git и Docker.

## Проверка конфигурации без запуска

Из корня checkout, после задания host-путей и остальных операторских переменных, для контейнерного Caddy:

```bash
docker compose -f docker-compose.yml -f deploy/compose.caddy.yml -f deploy/compose.workspace.yml config --quiet
```

Для уже установленного host proxy вместо Caddy overlay:

```bash
docker compose -f docker-compose.yml -f deploy/compose.host-proxy.yml -f deploy/compose.workspace.yml config --quiet
```

Это проверка Compose-модели, не доступности файлов из контейнера, прав UID 1001, сети, TLS или готовности пилота. `config` без `--quiet` может напечатать runtime-секреты; такой вывод не публиковать. Запуск/пересоздание контейнера — отдельное действие пользователя после проверки файлов и topology. Не запускать оба варианта proxy одновременно.

На текущем новом сервере к первой команде добавляется последним `-f deploy/compose.new-server-ip.yml`. Штатные deploy/rollback-скрипты делают это автоматически по точному `DEMEU_DOMAIN=84.247.161.211`, а их health gate требует одновременно точный commit, страницу кабинета и ответ auth-bootstrap `{ enabled: true, actor: null }`.

## Рестарт, backup и rollback

После выбора storage singleton фиксирует resolved-путь либо memory mode. Изменение `DEMEU_DATA_DIR` в работающем процессе, включая dev/HMR, требует рестарта: приложение не продолжает незаметно обслуживать старый memory store/volume и не мигрирует данные само. Эквивалентные пути к тому же каталогу через `.` допустимы. Периодическая очистка также проверяет выбранный режим.

Перед backup остановить единственный writer. Согласованный комплект включает существующие файлы состояния `sessions.json`, `referrals.json`, `deliveries.json` (журнал исходов отправки) и отдельный accounts JSON. Журнал создаётся при использовании доставки; отсутствие файла до первой отправки допустимо. Не копировать только referrals: будут потеряны связь с опросом, защита от повторной отправки и текущие права. Секрет подписи из `.env` хранится отдельно под той же защитой; его ротация отзывает старые browser cookie. Копии snapshot и accounts должны иметь доступ не шире оригиналов. Restore сначала проверяется в отдельном приватном каталоге с единственным тестовым экземпляром и без внешних отправок.

При deploy/rollback приватные mounts сохраняются. Откат к приложению, не понимающему новую schema version, должен закрыть доступ, а не перезаписать файлы пустым состоянием. Не выполнять `down -v` и не удалять host-каталог как часть обновления. Pending/failed доставка после рестарта требует проверки; автоматического повторного Telegram send нет.
