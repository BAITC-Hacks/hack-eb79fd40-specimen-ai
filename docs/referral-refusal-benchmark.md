# Offline benchmark риска отказа по направлению

## Граница задачи

Задача B3 разблокирована постановкой Ардана в ClickUp. Входной аудит сохраняет
767 130 строк и 84 081 строку с `is_refused == 1`. Для обучения и оценки
используются только зрелые непротиворечивые исходы: ровно один из флагов
`is_refused` и `hospitalized` равен единице. Причина отказа и снимок
комплектности для этой версии не требуются. Это меняет готовность B3, но не
постановку и метрики существующего D1 benchmark.

Benchmark остаётся offline-исследованием. Он не подключён к Next.js, карточке
направления или production scoring. Решение об интеграции принимается отдельно
после отчёта, проверки переноса и Python ↔ TypeScript parity.

## Данные и разбиение

Вход зафиксирован SHA-256 в коде и содержит 767 130 направлений за январь–март
2025 года. Из них 3 962 строки без зафиксированного исхода исключаются как
цензурированные, одна строка с обоими исходами — как конфликтующая. Итоговая
когорта содержит 763 167 строк: 84 080 отказов и 679 087 госпитализаций.
Точная выбраковка общей популяции и каждого календарного месяца записывается
в отчёт. Лицензия источника имеет статус `not_verified`; исходные строки, коды
направлений и значения категорий в отчёт не копируются.

Разбиение строго календарное:

- январь — обучение;
- февраль — выбор регуляризации и рабочего порога;
- март — test, который считается после завершения выбора.

Март ранее анализировался в handoff, поэтому он не заявляется новым слепым
набором.

## Признаки и защита от утечки

В модель входят только поля, разрешённые постановкой на момент регистрации:

- профиль койки;
- код МКБ-10;
- направляющая и принимающая медицинские организации;
- территориальный тип;
- источник финансирования;
- цель направления.

Идентификатор используется только для проверки исходного набора, дата
регистрации — только для временного split. Исключены `planned_dt`,
`polyclinic_dt`, производные лаги и флаги, исход госпитализации, целевая метка
как признак, поля операции, календарные производные и поля неоднозначного join.
Полный список фиксируется в отчёте и проверяется fail-closed verifier.

## Сравнение

Pipeline сравнивает:

1. константу, равную январской доле отказов;
2. сглаженную частоту по паре `hospital_mo + bed_profile` с fallback через
   принимающую организацию, профиль и общую частоту; коэффициент сглаживания
   выбирается на феврале из фиксированной сетки;
3. one-hot logistic regression без балансировки классов, чтобы вероятности
   сохраняли калибровочный смысл.

Для каждого метода порог выбирается на феврале по максимальному F1. На марте
публикуются PR-AUC, Brier, precision, recall, F1 и агрегированная калибровка по
децилям. Модель считается лучше частотного baseline только при строго большем
test PR-AUC; иначе отчёт рекомендует baseline. Это рекомендация для следующей
задачи, а не runtime-активация.

## Контракт будущей карточки

Карточка передаёт только семь регистрационных полей выше. Scorer возвращает
`refusal_probability_among_mature_outcomes`, выбранный на validation
`working_threshold`, один из двух диапазонов (`probability < threshold` или
`probability >= threshold`), `method`, `model_version` и метку
экспериментальных ограничений. Это условная вероятность отказа среди зрелых
непротиворечивых исходов. Интерфейс не должен показывать её как подтверждённый
исход и не должен подключать scorer до отдельного решения об интеграции.

## Воспроизведение

```bash
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python -r scripts/referral_ml/requirements.txt
.venv/bin/python -m scripts.referral_ml.train_refusal \
  --input '/home/almaz/Downloads/Telegram Desktop/demeu-data-handoff-2026-09-19/referrals_features.parquet' \
  --report reports/referral-refusal-baseline-v0.json \
  --model-output data/processed/referral-refusal-baseline-v0.joblib
.venv/bin/python -m scripts.referral_ml.verify_refusal_report \
  reports/referral-refusal-baseline-v0.json \
  --model data/processed/referral-refusal-baseline-v0.joblib
.venv/bin/python -m unittest discover -s tests/referral_ml -p 'test_*.py'
.venv/bin/ruff check scripts/referral_ml tests/referral_ml
```

Parquet и `joblib` остаются в игнорируемом каталоге. В git входит только код,
документация и агрегированный JSON-отчёт без исходных строк и идентификаторов.
