# Кабинет Demeu — новый UI/UX

Запрос пользователя 13.09.2026: полностью переделать админку после изучения аналогов, добавить рабочие страницы и обзоры для разных ролей; закончить также независимые от внешних материалов проверки. Worktree `september-foundation`, без commit/push/deploy. Актуальные задачи ClickUp являются PRD, отдельный документ не является блокером.

## Phase 0 — исследование и разрешённые интерфейсы

Класс T3: несколько UI-потоков поверх существующих контрактов. Главный агент прочитал SPINE целиком, Work-Plan 1.3 (ошибки/повтор вместо белого экрана), UX §4.1–4.2, сентябрьское дополнение, реальные page/client/types/CSS. Специалисты product_tasks и foundation_review независимо проверили API, роли, повтор команд, сохранность идентичности записи и доступность. Каждый использовал vault-rag; июльский Design-Handoff и сентябрьский foundation полезны для safety, но их перечень реализованных страниц устарел — факты сверены с кодом.

Визуальные первоисточники: просмотрены публичные скриншоты Healthie и рекомендации Carbon. Для Medplum доступен результат поиска документации; прямое открытие страницы завершилось 502, полный интерфейс не проверен:

- [Healthie Provider Dashboard](https://help.gethealthie.com/article/535-your-provider-dashboard): рабочий обзор, ближайшие события и действия отделены от аналитики. Берём приоритет действий, не чужой набор клинических функций.
- [Healthie Visualize](https://help.gethealthie.com/article/729-reporting-dashboards): отдельная аналитическая область, компактные показатели над графиками и таблицами. Финансовые/клинические метрики в Demeu не переносим.
- [Medplum Provider](https://www2.medplum.com/docs/provider): референс разделения клинических и операционных поверхностей; не зависимость приложения.
- [Carbon UI shell](https://carbondesignsystem.com/components/UI-shell-left-panel/usage/): постоянная боковая навигация для частого переключения между разделами, не более двух уровней.

Allowed APIs: существующие `/api/workspace/auth`, `/api/referrals`, `/api/referrals/:id`, `/events`, `/examinations`, `/patient-memo`, `/notify`, `/api/workspace/intakes`, `/api/workspace/aggregates`, `/api/link`. Формы строго из `lib/referrals/types.ts`, авторизация из `lib/workspace-api.ts` и `workspace-auth.ts`. Агрегаты НЕ принимают query-параметры. Никаких придуманных team/appointment/region API.

Два кандидата: A — перекрасить старые вкладки; B — общий role-aware shell и отдельные URL поверх тех же данных. Выбран B: текущая страница смешивает вход, список, создание, опросы и аналитику; косметика не решает навигацию. Возражение против B — новые страницы размножают fetch/state и могут потерять idempotency. Снимаем общими request/command/auth helpers, явной identity gate и regression-проверками.

Pre-mortem: аналитик получает персональные строки ради подсчёта; неизвестное становится нулём; переход A→B отправляет действие для B при отображении A; роли отозваны, старые данные остаются; календарная дата автоматически становится явкой. Защита: серверные DTO, подавление малых групп, loadedId===routeId, снятие приватного UI при auth failure, независимые подтверждения.

## Phase 1 — оболочка и визуальная система

Исполнитель ml_tasks. Скопировать проверенные auth/request semantics из `app/workspace/client.tsx`; вынести общий layout/context без изменения API. Sidebar 232px, белая поверхность, светло-серый фон, тёмный текст, teal акцент; локальный IBM Plex Sans в заголовках и интерфейсе, Demeu wordmark сохранён. Compact KPI/table/form, 8px spacing, маленькие радиусы и спокойные границы. Мобильное раскрываемое меню, skip-link, фокус, reduced motion. Не менять пациентский чат/глобальную тему.

Проверки: auth/loading/error/login/logout, deep links, role navigation, 401/403 снимают старый приватный экран; нет мёртвых registration/password-reset кнопок.

## Phase 2 — рабочие страницы

Исполнитель product_tasks. Переиспользовать `workspaceRequest`, `useWorkspaceCommand`, labels/date helpers из client.tsx и DTO types.ts:

| URL | Содержание | Роли |
|---|---|---|
| `/workspace` | Рабочий обзор роли: показатели, этапы, события/действия | Все, analyst только aggregate DTO |
| `/workspace/referrals` | Реестр, поиск, фильтры, ссылки на карточки | doctor/owner |
| `/workspace/referrals/new` | Создание вручную или из завершённого опроса | doctor/owner |
| `/workspace/intakes` | Опросы, сводка, доставка, ссылка пациенту | doctor/owner |
| `/workspace/calendar` | Календарь подтверждённых дат госпитализации | doctor/owner |
| `/workspace/activity` | История подтверждений, не журнал всех действий системы | doctor/owner |

Проверки: filtered-empty отдельно от пустого реестра; подсчёт направлений, не уникальных пациентов; все кнопки работают; собственная/организационная область обозначена. Календарь не добавляет расписание приёмов, авторегистрацию или автоподтверждение явки.

## Phase 3 — карточка направления

Исполнитель storage_techdebt. Сохранить команды существующей `referrals/[id]/page.tsx`, переразложить обзор / подтверждения / обследования / историю / памятку. Состояния формы привязаны к routeId и загруженному id. Не переносить клиническую сводку в patient memo. История с автором, reason, recordedAt и отдельно occurredAt, без сырого JSON для пользователя.

Проверки: исправление требует причину; null queue/date/attendance сохраняются; revision conflict не применяет команду автоматически; Telegram ambiguity не повторяет отправку. Переход между id и запоздалый GET никогда не показывают данные предыдущей записи под новым адресом.

## Phase 4 — аналитика и качество

Исполнитель foundation_review. `/workspace/analytics`: этапы и длительности, для doctor/owner профили и фиксированная 30-дневная история локальных наблюдений. `/workspace/data-quality`: происхождение и покрытие сведений, ограничения справочника/прогнозов. `/workspace/settings`: реальные сведения текущей учётной записи, область прав и порядок изменения оператором, не фиктивный CRUD сотрудников.

Проверки: analyst не запрашивает referrals/intakes, не видит free-text/ID/profile/timeline. suppressed/null не заменены нулём. Доли имеют знаменатель, длительности — число известных наблюдений. Текущие этапы не названы конверсионной воронкой, история кабинета не названа очередью Портала.

## Phase 5 — проверка и передача

Независимое review, narrow unit/static view tests → полный `npm test`, `npm run lint`, `npx tsc --noEmit`, build, eval check. Playwright: три роли, прямые URL/назад/перезагрузка, поиск/пустые результаты, создание/исправление/история, подавленные агрегаты, мобильная ширина, клавиатура, ошибки и отсутствие утечек. Синтетические данные только в отдельном локальном каталоге, внешние AI/Telegram отключены. После проверки оставить локальный сервер доступным для пользователя. Прогнозы/нормативные требования/новые права не придумывать в ожидании ответов Ардана.
