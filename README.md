# Demeu — AI-триаж и первичный сбор анамнеза

Прототип для отборочного этапа **GovTech Camp** (партнёр — inDrive).

Ассистент собирает первичный анамнез пациента в диалоге, аналитический слой
даёт **маршрутизацию к специалисту, приоритет срочности и предварительную
гипотезу с объяснением**, а сводка уходит врачу. Продукт **не ставит диагноз** —
финальное решение принимает врач (human-in-the-loop).

## Проблема

Первичное звено госполиклиник перегружено: ~30 мин на приём, из них ~15 —
ручной сбор анамнеза; пациенты попадают не к тому специалисту; срочные случаи
не приоритизируются. Форма-анкета не разбирает свободный текст на естественном
языке — нужен NLP-разбор, скоринг и маршрутизация.

## Как работает (end-to-end)

1. Врач генерирует персональную ссылку и отдаёт пациенту (`/`).
2. Пациент открывает `/c/<token>`, проходит **агентный опрос анамнеза**.
3. Когда данных достаточно, запускается **аналитический слой**:
   извлечение сущностей → детекция красных флагов → скоринг срочности →
   классификация специальности → предварительная гипотеза.
4. Сводка приходит врачу (в проде — в Telegram через Hermes; в демо —
   панель на экране и `console.log` / вебхук).

## AI/ML-компонент

Не «чат без аналитики», а структурированный аналитический слой (все подходы —
из разрешённого списка ТЗ):

| Компонент | Где | Задача |
|-----------|-----|--------|
| Извлечение сущностей | `lib/triage.ts` | Свободный текст → структурированный анамнез |
| Скоринг срочности + красные флаги | `lib/triage.ts`, `lib/redflags.ts` | Приоритет + флаги-триггеры с объяснением |
| Маршрутизация к специальности | `lib/triage.ts` | Классификатор top-N с вероятностями |
| Предварительная гипотеза | `lib/triage.ts` | Версия для врача (не диагноз) |

**Шов с ML-треком.** `lib/triage.ts` (`analyze()`) сейчас реализован на LLM
(claude-sonnet-5) + rule-based флагах, чтобы демо работало end-to-end. Обученные
модели (скоринг/маршрутизация на **DDXPlus** + открытых symptom-датасетах)
подменяются внутри `analyze()` без изменения формата `TriageResult`. Красные
флаги (`lib/redflags.ts`) остаются rule-based ради explainability.

## Explainability

По каждому выводу видно: почему такой приоритет (сработавшие признаки/флаги с
цитатой из текста), какие данные повлияли, уверенность гипотезы и явная
оговорка «это не диагноз, решает врач».

## Данные

- **DDXPlus** — публичный синтетический датасет (симптомы/антецеденты/патологии/
  дифференциал) под скоринг и маршрутизацию.
- Открытые symptom→disease датасеты — обучение/валидация извлечения.
- **МКБ-10** — нормализация и справочник.
- Синтетика под КЗ-специфику (рус/каз) с описанной методологией.

В демо аналитика работает на LLM поверх текста пациента; обучающие данные
подключаются в ML-треке (см. шов выше).

## Запуск

Нужен Node.js 20+.

```bash
npm install
cp .env.example .env        # впишите ANTHROPIC_API_KEY
npm run dev                 # http://localhost:3000
```

1. Откройте `/`, нажмите «Сгенерировать ссылку».
2. Откройте ссылку в новой вкладке — пройдите путь пациента.
3. После завершения опроса появится сводка «для врача».

### Переменные окружения

| Переменная | Обязательна | Назначение |
|------------|-------------|-----------|
| `ANTHROPIC_API_KEY` | да | Ключ Anthropic API |
| `HERMES_WEBHOOK_URL` | нет | Вебхук для доставки сводки врачу (Telegram/Hermes) |

## Демо-сценарии

- **Срочный:** мужчина 58, боль в груди + одышка → красный флаг, `неотложно`,
  маршрут кардиология/скорая.
- **Плановый:** женщина 34, боль в пояснице 2 недели, без флагов → `планово`,
  маршрут терапевт/невролог.
- **Отсев:** насморк 1 день → короткий путь, гипотеза, запись не требуется.

## Ограничения

- Хранилище сессий — in-memory (для прототипа; в проде — БД).
- Список красных флагов — базовый MVP, согласуется с практикующими врачами.
- Аутентификация ссылок не реализована (демо).
- Врачебная сторона (Hermes-Telegram) — отдельный трек, здесь точка стыка.
