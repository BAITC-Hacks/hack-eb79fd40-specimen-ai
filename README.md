# Demeu — AI-триаж и первичный сбор анамнеза

Demeu — MVP для госполиклиник: врач создаёт персональную ссылку, пациент
проходит короткий диалог, а аналитический слой формирует предварительную
гипотезу, приоритет срочности, маршрут к специальности и объяснение. При
настроенном Telegram-боте врачу отправляются структурированный текст и PDF.

Продукт **не ставит диагноз**. Красные флаги и правила безопасности имеют
приоритет над моделью, а финальное решение принимает врач.

## Что работает в MVP

1. Врач создаёт персональную ссылку на главной странице.
2. Пациент подтверждает начало опроса и отвечает в веб-чате по ссылке
   `/c/<token>`.
3. LLM-адаптер извлекает анамнез и структурированный вектор признаков.
4. Правила проверяют красные флаги только в репликах пациента. LR-модель
   ранжирует патологии, а таблица маршрутизации агрегирует вероятности по
   специальностям и задаёт базовую срочность.
5. При низкой уверенности модель воздерживается, и работает LLM-fallback; при
   отказе адаптера остаётся rules-only путь. Emergency-правила доминируют в
   любом режиме.
6. После завершения сводка сохраняется в сессии и отправляется врачу через
   собственного Telegram-бота. Повторная финализация идемпотентна.

Explainability строится из цитат пациента, причин срочности, top-вкладов
признаков и уверенности. Веб-интерфейс врача и пациента — принятый продуктовый
дизайн; отдельной административной панели в MVP нет.

## Быстрый локальный запуск

Нужны Node.js 24 и npm. Реальные ключи не должны попадать в git.

```bash
npm ci
cp .env.example .env
npm run dev
```

Откройте <http://localhost:3000>, создайте ссылку и пройдите путь пациента в
новой вкладке. Для живого диалога нужен `ANTHROPIC_API_KEY`; без Telegram-
реквизитов сводка формируется, но внешняя доставка недоступна.

Проверки без внешней сети:

```bash
npm run lint
npx tsc --noEmit
npm test
npm run build
npm run eval -- --allow-unvalidated --check
```

### Переменные окружения

| Переменная | Назначение |
|---|---|
| `ANTHROPIC_API_KEY` | Живой LLM-адаптер диалога и анализа |
| `TELEGRAM_BOT_TOKEN` | Токен собственного Telegram-бота |
| `TELEGRAM_DOCTOR_CHAT_ID` | Получатель врачебной сводки |
| `DOCTOR_ACCESS_CODE` | Опциональная защита создания ссылок |
| `APP_BASE_URL` | База персональной ссылки; локально `http://localhost:3000` |
| `NODE_ENV` | Режим Next.js |
| `TLS_BRANCH` | Принятая для целевого VPS ветка `branch-b-caddy`; локальный runtime её не использует |

### Docker

```bash
cp .env.example .env
docker compose up --build -d
curl --fail http://localhost:3100/api/healthz
```

Compose по умолчанию публикует приложение только на
`127.0.0.1:3100`. Публичный HTTPS/VPS-деплой не заявлен как готовый: внешний
запуск, TLS и smoke на целевой машине ещё требуют отдельного подтверждения.

## Что подтверждено живыми проверками

- Один локальный end-to-end прогон срочного сценария прошёл через API, два
  запроса Anthropic, анализ, PDF и доставку. Итог сохранил `emergency` и
  `chest_pain`; LR-модель безопасно воздержалась с `low_confidence`, поэтому
  результат пришёл из `llm_fallback` без неподтверждённых патологий и вкладов.
- Telegram Bot API принял `sendMessage` и `sendDocument` с HTTP 200. Это
  подтверждает принятие запросов API, но не прочтение сводки человеком.
- LR-модель подключена в production runtime; Python↔TypeScript parity зелёный
  на 150/150 примерах, а `/api/healthz` берёт `model_version` из загруженного
  артефакта.
- Read-only SSH-разведка целевого VPS принята: Docker/Compose доступны, порты
  80, 443 и 3100 были свободны, выбрана ветка B с отдельным Caddy. Повторный
  preflight и dry-run rsync прошли без мутаций VPS.

Публичный deploy остановлен fail-closed до появления commit SHA, который
точно описывает принятые байты worktree. Поэтому публичные HTTPS/TLS, L1/L2
smoke и три сценария на production пока не заявляются как выполненные.

## Данные и методология

Ниже восемь явных пунктов data-критерия. Проверенные факты воспроизводятся
офлайн-скриптами; публичные показатели качества берутся только из
[`eval/report.json`](eval/report.json), рассчитанного TypeScript-путём.

### 1. Источник и происхождение

Используется синтетический медицинский датасет **DDXPlus v15**: официальный
[Figshare article 20043374](https://figshare.com/articles/dataset/DDXPlus_Dataset/20043374),
DOI `10.6084/m9.figshare.20043374.v15`. Локальный provenance фиксирует URL,
версию, дату получения, идентификаторы файлов и контрольные суммы в
`data/raw/PROVENANCE.json`; сырые файлы в git не входят.

### 2. Лицензия и атрибуция

Лицензия — [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) по
metadata официальной страницы Figshare. В опубликованном file list отдельного
LICENSE не было; локальный `data/raw/LICENSE` — запись provenance на основе
metadata, а не самостоятельный файл лицензии издателя.

### 3. Структура и объём

Релиз содержит словарь evidences, словарь патологий и CSV split-файлы с
`AGE`, `SEX`, `PATHOLOGY`, `EVIDENCES`, `INITIAL_EVIDENCE` и
`DIFFERENTIAL_DIAGNOSIS`. Фактические raw-размеры train/validate/test:
**1 025 602 / 132 448 / 134 529** строк. Найдено **223 evidences**
(208 binary, 10 categorical, 5 multi-choice), **49 raw-патологий** и непустой
`icd10-id` у **49/49**. Шкала severity: 1–5, меньшее значение означает более
тяжёлое состояние.

### 4. Очистка и разделение выборок

Проект работает только со взрослыми (`AGE >= 18`) и удаляет полные дубли по
ключу `(AGE, SEX, PATHOLOGY, EVIDENCES)`. После adult-only фильтра и
внутрисплитовой дедупликации осталось **814 240 / 108 199 / 109 732** строк.
Затем decontamination с приоритетом train → validate → test удалила пересечения
между split: финальные размеры — **814 240 / 104 770 / 105 723**, а все три
попарных overlap равны **0**. Из adult-only label space исчезли исключительно
детские классы Bronchiolitis и Croup; runtime `class_order` содержит
**47** классов.

### 5. Признаки и целевая переменная

Цель LR — родная метка `PATHOLOGY`, а не срочность и не специальность:
таких целевых меток в DDXPlus нет. Вектор содержит **975 признаков**:
972 one-hot evidence-колонки и `age_norm`, `sex_m`, `sex_f`. Порядок и
препроцессинг читаются из `models/triage-lr-v1.json`, поэтому Python-обучение и
TypeScript-инференс используют один контракт. C/M значения кодируются как
`E_x@V_y`; неизвестные признаки не превращаются в выдуманные колонки.

### 6. Почему multinomial logistic regression

LR соответствует закрытому многоклассовому label space, выдаёт вероятности,
работает на разреженном one-hot векторе, быстро и детерминированно исполняется
в TypeScript и позволяет показать вклад каждого признака. Артефакт — один JSON,
Python в production-образ не входит. Порог воздержания финальной модели —
`0.5036984086036682`; model fallback остаётся частью рабочего пути. Срочность и
маршрутизация выводятся отдельной прозрачной таблицей, а safety-правила всегда
побеждают вероятностный результат.

### 7. Методика оценки

Eval содержит **48 карточек**: 28 `flat`, 12 `dialog` и 8 ручных red-flag
сценариев (5 позитивных и 3 негативных). DDX-карточки детерминированно
отрендерены из decontaminated held-out строк; родная `PATHOLOGY` остаётся gold.
Прогон выполняет `scripts/eval.ts` через production `lib/model.ts` и
`lib/triage.ts`. Publication guard пересчитывает агрегаты из `per_case`,
проверяет SHA входов и блокирует подменённые показатели.

### 8. Ограничения данных и оценки

- DDXPlus — синтетика и не доказывает качество на пациентах Казахстана.
- Демо №2 с болью в пояснице находится вне label space. Для демо №3 есть
  классы-кандидаты, но покрытие конкретного сценария не доказано.
- Таблица `data/pathology_map.json` имеет `validated:false`; результаты
  routing/urgency нельзя трактовать как врачебную или клиническую валидацию.
- Текущий eval работает в режиме `no-LLM` с идеализированным структурированным
  extraction input. Он измеряет верхнюю границу модели и не доказывает качество
  извлечения из живого чата end-to-end.
- M9/M10 extraction F1 в этом режиме не запускались и остаются `null/not_run`.

## Качество: только production TypeScript eval

Источник таблицы — текущий `eval/report.json`; показатели Python-обучения здесь
не публикуются. Режим — **`no-LLM`**: модель получила идеализированный
структурированный extraction input. Поэтому Top-1/Top-3 не являются метрикой
извлечения или полного chat end-to-end пути.

| Метрика | Фактический результат | Статус |
|---|---:|---|
| Pathology Top-1 | **40/40 (100%)** | measured, ideal-extraction upper bound |
| Pathology Top-3 | **40/40 (100%)** | measured, ideal-extraction upper bound |
| M11 abstain | **0/40 (0%)** | measured |
| M12 coverage-adjusted Top-1 | **40/40 (100%)** | measured |
| M6 under-triage | **0/40 (0%)** | UNVALIDATED |
| Routing Top-3 differential | **40/40 (100%)** | UNVALIDATED |
| Urgency accuracy | **39/40 (97.5%)** | UNVALIDATED |
| Manual emergency recall | **5/5 (100%)** | measured |
| Manual emergency specificity | **3/3 (100%)** | measured |
| M7b table-derived emergency recall | **7/7 (100%)** | UNVALIDATED |
| M9/M10 extraction F1 | **null/not_run** | LLM extraction не измерялось |
| Golden invariants I1–I7 | **PASS** | все проверки зелёные |

Все routing/urgency числа выше получены **на невалидированной врачами таблице**
и показывают согласованность кода с `data/pathology_map.json`, а не клиническую
правильность. Полный отчёт, знаменатели, caveats и per-case результаты находятся
в [`eval/report.md`](eval/report.md) и [`eval/report.json`](eval/report.json).

## Ограничения MVP

- Сессии хранятся in-memory; перезапуск процесса очищает их.
- Перезагрузка страницы пациента начинает новый опрос: восстановление сессии
  между вкладками не реализовано.
- Врачебная валидация таблицы маршрутизации ещё не проведена.
- Локальный live-прогон подтверждает один срочный сценарий, но не заменяет
  три production-сценария и не подтверждает публичные HTTPS/TLS или прочтение
  Telegram-сводки человеком.
- MVP не выполняет запись пациента, напоминания и последующее сопровождение.

## Стек

Next.js 15.5 (App Router), React 19, TypeScript, Anthropic SDK, Docker,
собственный Telegram Bot API adapter. Python используется только офлайн в
`scripts/`; production runtime загружает JSON-артефакт модели.
